# 连接路由：使用与升级维护

## 使用入口

打开 `dist/Mirra RustDesk Test.app` → Settings → **连接路由**。入口在 Network 与 Display 之间，原页面的内容和功能没有改动。

- **ID 服务**：添加、编辑名称、主机名/IPv4 和服务器公钥。当前使用 RustDesk 标准端口（在线查询 21115，ID 21116）；地址不要填写 URL 或端口。公钥必须是该服务的 32 字节 Base64 公钥。
- **设备路由**：读取当前已加载地址簿中的普通数字 ID、本机收藏，以及手动添加的 ID。选择“自动”或指定服务。保存立即写入测试客户端本机配置，下次新建连接生效，已有会话保持其连接上下文。
- **自动**：并行询问所有已配置服务，每边总时限两秒；只有一个服务报告在线才选择它。另一边无法访问时，只要已有唯一在线结果仍可连接。多个在线结果报冲突；全部离线报离线；没有在线结果且存在查询失败报无法确认，不猜测国家、不回退到全局设置。
- **指定服务**：不做在线归属查询，直接使用该服务及公钥，保留原账号凭证；原连接流程处理离线、权限、账号或密码错误，不切换服务重试。地址簿在线状态也以指定的服务为准。
- **清除规则**：设备行右侧的 × 恢复自动；手动添加且不在地址簿/收藏中的 ID 会从此列表消失。
- **删除服务**：至少保留一个；被设备规则引用时先调整规则，不能直接删除。服务使用稳定标识，改名和改变排列不会影响设备规则。
- **关闭新增功能**：恢复原 Network 全局 ID 服务路径。原全局设置仍负责本机注册；账号 API 仍在原 Network 页面配置，不随设备服务器选择而改变。

交付状态：启用、保留美国和中国服务、无单独指定的设备规则（全部自动）。验收中创建的临时服务和临时设备规则已清理。原账号登录保持，不需要重新登录。

普通数字 ID 的自动和手动选择都要求当前 Mirra Account 会话；API 保持 `https://rustdesk.mirra-xr.com`。原设备密码和服务端验证策略不变。客户端的本地登录要求不等于服务器禁止其他客户端匿名连接。IP、域名、显式 `ID@server` 等原有连接方式仍沿用原路径，不纳入本次路由配置。

## 独立模块与数据边界

| 模块 | 职责 |
|---|---|
| Rust `src/auto_id_config.rs` | 本机配置、版本及地址/公钥/规则校验；旧配置没有新增选项时使用中美默认值 |
| Rust `src/auto_id_query.rs` | OnlineRequest、并行查询、响应解析和两秒超时 |
| Rust `src/auto_id_policy.rs` | 不依赖 UI 和配置存储的在线结果判定 |
| Rust `src/auto_id.rs` | 登录检查、自动/手动会话路由、批量在线状态，以及测试应用隔离初始化 |
| Dart `desktop/connection_routing/routing_config.dart` | 页面数据模型、表单校验和版本化 JSON |
| Dart `desktop/connection_routing/routing_store.dart` | 通过原有 LocalOption 接口读取和保存本机配置 |
| Dart `desktop/connection_routing/routing_page.dart` | 独立页面、服务编辑、设备选择和保存反馈 |

配置选项为 `mirra-id-routing-v1`，存在测试应用独立的 LocalConfig 中。数据契约示例（不包含账号凭证或设备密码）：

```json
{
  "version": 1,
  "enabled": true,
  "servers": [
    {"id": "us", "name": "美国", "host": "us.rustdesk.mirra-xr.com", "public_key": "<服务器公钥>"},
    {"id": "cn", "name": "中国", "host": "rustdesk.mirra-xr.com", "public_key": "<服务器公钥>"}
  ],
  "device_routes": {"123456789": "us", "987654321": "cn"}
}
```

没有规则或空服务标识表示自动。UI 只写本机 LocalOption，不向云端地址簿增加路由字段。没有添加 Flutter/Rust FFI 接口，没有修改共享 trait、函数签名、账号 API、协议或服务端代码。Rust 和 Dart 两端均校验数据；格式错误明确失败，不回退到默认服务。

## 构建与升级

固定上游版本为 RustDesk 1.5.0（`fada664df7a294d1d1a9ca3e7cd3637069122f17`）；Rust 1.81.0、Flutter 3.24.5、Dart 3.5.4 和 flutter_rust_bridge 1.80.1。原 `hbb_common` 子模块未改动，未新增 Cargo 或直接 Dart 依赖。Flutter 锁文件按固定 SDK 的依赖约束重新解析，原生插件版本未改变。

先准备 `mirra/BUILD.md` 中列出的固定工具链；这些脚本不自动下载安装依赖。默认构建目录为被忽略的 `mirra/workspace/`，也可通过 `MIRRA_WORKSPACE` 指定已有本机目录。

```sh
./mirra/build-core.sh
./mirra/build-ui.sh
./mirra/test-routing.sh
MIRRA_LIVE_TEST_IDS="<美国ID1>,<美国ID2>,<中国ID1>,<中国ID2>" ./mirra/test-routing.sh --ignored
./mirra/test-ui.sh
python3 mirra/package-test-app.py --replace --with-ui
```

重打包之前关闭测试应用。`build-ui.sh` 使用 Flutter 官方 assemble 编译 Dart AOT、资源及对应引擎；只在测试构建启用 `MIRRA_ROUTING_UI=true`。原生窗口、原生插件及可执行文件复用原版 1.5.0 的副本，Rust 核心自行编译。打包校验原核心导出符号，进行本机 ad hoc 签名，并验证签名。

这次没有安装完整 Xcode；使用现有 Command Line Tools。Flutter 3.24.5 的 macOS AOT 编译器是 Intel 程序，本机已安装苹果 Rosetta 2 编译依赖。后续上游如果改变原生窗口、插件或 FFI，不应继续复用不匹配的组件；届时需要完整原生构建环境（包括 Xcode），升级所有匹配组件并重新验收。

升级建议：固定新的上游 tag，在独立 checkout 合并 `mirra-routing` 分支的定制提交，保留版本化本机配置和隔离标识，生成匹配的新桥接代码，再构建测试包。先检查以下四个集成入口，再检查 SDK/插件兼容性；不要将官方更新直接覆盖到定制应用。

## 手机连接本机

新增的自动路由仅作用于测试客户端主动连接远端电脑。本机仍向 Network 的全局 ID 服务注册；手机正常版需要配置同一服务，并使用测试应用显示的独立 ID。测试配置和正式配置各自保存设备密码，新测试配置不会自动继承正式应用的永久密码；请在测试版 Security 页面自行设置后再连接。公开仓库不含任何设备密码或本机登录会话。
